Status: retained after source, package, browser and actual-consumer verification; no npm publication or merge.

The requested outcome is measured net benefit with unchanged behavior, followed by
complete verification and a PR. The baseline is
`59a30cb4fd031463eb7f9335d1faa80a484ca93a`. The companion best-agent experiment uses

## Review before implementation

The current built CLI `product-markdown-stream-12ms` profile identifies
`layoutMarkdownBlocksCached`, `blockLayoutSignature` and `inlineSegmentSignature` as
hotspots, together with Vue reactive reads. This is a renderer cache cost, not evidence
that terminal output or character width should be rewritten. The best-agent profile
independently identifies row-version field construction and hashing.

Classification: private presentation computation, no public API or authority change.
The permitted upstream change removes temporary arrays in signature construction while
preserving every character of the existing signature and observing mutable inputs on
every call. No identity-only cache, reactive tracking bypass, weaker width-provider
invalidation, field removal or new persistent cache is permitted. The renderer still
consumes the same blocks and emits the same rows, styles, graphics, links and actions.

No blocking finding for this scope. Residual risks: string coercion and separators,
in-place updates, reactive tracking, non-ASCII/control characters and package/browser
behavior. Verify all before retention. This work introduces no source error producer,
mapper, model/tool call, sibling decision or Run transition. Original error text passes
through the same existing layout; the cache cannot reclassify it.

### Follow-up review: snapshot publication

The reactive cost traces to `examples/agent-console/src/transcript-store.ts`:
`markdownSource.blocks` produces a new readonly snapshot, `syncMarkdownBlocks` assigns
that snapshot, and reset assigns a new empty array. There is no nested block writer in
the store; the publication controller and component observe replacement of the ref.
Using the already-imported `shallowRef` for this one snapshot preserves all publication
notifications and values while avoiding the store's deep proxy construction. It does
not strip proxies from arbitrary caller blocks, alter the library's mutable-input
contract or change scheduling. This one-line Application/example change is admitted
for paired measurement, with snapshot/clear/replay publication and mounted rendering
tests required. It is not a claim that best-agent uses this example store.

### Follow-up review: one-shot layout

The actual best-agent `markdown-rendering.ts` calls `layoutMarkdownBlocks` for source-line
measurement and rendered inline/code content. That one-shot API currently creates all
cache signatures and entries through `layoutMarkdownBlocksCached`, then immediately
discards the cache. Directly collecting `layoutMarkdownBlock` rows preserves the same
normalization, empty row and width-provider scope without producing the unused cache.
No cache caller changes, no field is removed from reusable cache identity, and no new
state/API is introduced. Admit this bounded alternative for exact cached/uncached output
comparison and the real consumer benchmark before retention.

The one-shot prototype did **not** demonstrate a stable benefit. Across three alternating
rounds its CPU medians were 52.18/48.07/59.14 ms versus 50.93/51.06/47.82 ms baseline;
wall times also varied substantially. It is reverted. The experiment command retains
the `oneshot` workload for reproduction, but the product still uses the original
cached-layout implementation at that public entry. Do not count fewer allocations or
an apparently redundant operation as measured user benefit.

## Experiment and verification scope

Compare exact signatures and complete layouts against the frozen baseline, with plain
and reactive blocks, all block forms, graphics/math, source errors, in-place mutations
and width changes. Repeat built CLI streaming and scroll scenarios in alternating
processes, and exercise packed browser/SSR/CLI entries. Run typecheck, lint, touched-file
format checks, the full test suite and relevant browser tests. The companion consumer
must retain its full repository gate; all cross-platform/package jobs run in the public
best-agent-releases repository with exact private source and encrypted diagnostics.

Report measured latency/CPU/memory and costs without claiming provider savings, billed
token reduction or task success from layout measurements. Rust retention requires a
whole-caller advantage after FFI/copies, not a faster isolated hash.

## Local observations

[Paired data](rust-ts-20261102.json) records five alternating signature rounds and three
built CLI rounds. Signature layout/cache values match on 6,000 plain/reactive mutation
cases; the attempted uncached path also passed that exact-output comparison before its
performance-based rejection. The signature-only plain-block median CPU is 2.274 → 1.858 ms (−18.3%); reactive
blocks are 7.932 → 8.145 ms (+2.7%). This is not an across-the-board win.

The completed CLI pairs use real mounted components, 6,000 seeded events, 400 product
timer ticks at a requested 12 ms cadence, and the source store's shallow snapshot change.
All original correctness assertions, replay hashes and post-measurement bottom-view
hashes match. Median process-tree CPU (including setup and equal verification) is
10,428 → 6,042 ms for Markdown streaming (−42.1%). The log-mode scroll control is
4,288 → 4,658 ms (+8.6%); its three p95 input-to-commit values are
28.91/23.29/21.72 → 32.33/27.41/22.52 ms. Preserve that control cost; no general scroll
speedup is claimed. Wall times are highly variable under observed foreign Vitest and
desktop load. These local pairs support further acceptance, not a cross-platform claim.

The initial CLI comparator incorrectly required the detached scroll viewport to land on
the same row across timer/wheel interleavings. A repeat of the **unchanged baseline**
reproduced the candidate's exact previously mismatching hash: the header changes from
`detached:7738` to `detached:7739` and the transcript shifts one row. Replay/source facts
are identical. The raw measured snapshot, 100 correlated wheel responses and original
assertions are retained. Only after recording timing, memory and stdout does the driver
issue the same explicit jump-to-bottom and compare the settled screen. This is a separate
deterministic output proof; it does not replace the measured interaction or discard a
source error. The paired baseline driver has the same diagnostic-only additions.

The first isolated baseline launch also failed package resolution because a root-only
node_modules symlink omitted nested example workspace links. A frozen offline install in
the baseline worktree resolved the actual package graph; no production fallback or test
waiver was added. All failures remain in local logs.

## Source and package checks

The full source suite passes (159 files, 2,300 tests); its nine conditional built-export
cases were subsequently enabled through `test:package-exports:dist`, which passes all
23 cases. Typecheck, lint, format, build, packed ESM/CJS/SSR/no-Mermaid consumption,
declaration consumers, Vite browser import and all six browser smoke cases pass.
Production instrumentation stripping and its positive/negative controls pass.

The additional consumer-bundle check initially failed before package loading: its
temporary manifest omitted `packageManager`, so Corepack selected an unavailable
machine-default pnpm 12.11.2 instead of the repository's declared version. The fixture
now copies the repository declaration; all four actual packed consumer bundle closures
pass. This changes only verification setup, without a global package-manager change,
dependency fallback or relaxed assertion. Documentation build passes; API diff reports
its existing missing-base-manifest skip contract. Final packed integration is recorded below.

The subsequent full rerun exposed two test-driver defects that are corrected before
acceptance. The twelve-entrypoint export-membership case exceeded Vitest's default
five-second guard during cold source transformation; that one case now has a 30-second
guard with every export/lazy-peer assertion retained. The 3D wheel/reset case read the
last pre-reset frame after a fixed 60 ms sleep. It now requires a new actual renderer
context after reset and checks the same zoom/velocity within one second, with cleanup
in `finally`. No renderer behavior, frame pacing or motion bound changes. Both focused
files pass; the subsequent complete source sweep also passes. The benchmark's literal emoji
joiner was also escaped to satisfy the repository Unicode-source check without changing
its runtime string or weakening the check.
